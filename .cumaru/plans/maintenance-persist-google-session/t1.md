# T1 — Add native persistent CEF profile support

## What to do

Teach the macOS CEF entry point to read `LAUFEY_CEF_PROFILE_PATH` before `CefInitialize`, expand a
leading tilde, and configure persistent CEF storage. Preserve the current temporary PID-scoped path
when the variable is absent so unrelated Laufey consumers retain their existing behavior.

## Context

The current runtime always uses `NSTemporaryDirectory()/laufey_cef_<pid>` as `root_cache_path`.
Because the process identifier changes on every bundle launch, Google receives a fresh browser
profile and asks for credentials again. The app cannot correct this after CEF initialization.

## Implementation

1. Read `LAUFEY_CEF_PROFILE_PATH` during macOS CEF settings construction.
2. Expand `~` with Foundation before converting the path to `CefString`.
3. Set `cache_path`, `root_cache_path`, and `persist_session_cookies` for the explicit profile.
4. Retain the temporary PID path as the fallback.
5. Build the CEF backend and exercise it through the application bundle.

## Done when

- [x] Laufey receives the bundle-provided profile path before CEF initialization.
- [x] The macOS CEF backend builds successfully.
- [x] A helper process reports the configured path as its `--user-data-dir`.
