# T2 — Integrate the profile into build and packaging

## What to do

Make the macOS build add the Laufey profile contract to `Info.plist` before code signing. Simplify
development to export the same environment directly, delete `run.sh`, and package the application
bundle as the release entry point.

## Context

`LSEnvironment` is read by Launch Services when the `.app` is opened. The property must be present
before signing because any later plist edit invalidates the bundle signature. The old launchers use
a timing-sensitive symlink watcher around Laufey's PID-scoped temporary directory and are no longer
needed after T1.

## Implementation

1. Add an idempotent plist configuration helper and call it before signing.
2. Replace the development symlink watcher with `LAUFEY_CEF_PROFILE_PATH`.
3. Remove `run.sh` and all packaging or test references to it.
4. Package `GoogleChatDeno.app` at the release archive root and document direct launch.
5. Pin the new Laufey release and bump the application patch version.
6. Update deterministic shell tests for the new build contract.

## Done when

- [x] Repeated plist configuration produces the expected stable value.
- [x] `dev.sh` is the only launcher script and is explicitly development-only.
- [x] The release workflow contains no `run.sh` dependency.
- [x] The application build and focused tests pass.
