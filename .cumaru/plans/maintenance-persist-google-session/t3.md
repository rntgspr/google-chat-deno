# T3 — Publish and verify the paired releases

## What to do

Commit and push the runtime and application changes, tag both repositories, wait for their GitHub
release workflows, and inspect the published assets. The application must only be tagged after the
new Laufey release is available for download.

## Context

The application workflow downloads a version-pinned Laufey CEF archive. Laufey's fork release branch
exists specifically to publish the CEF 150 runtime without changing the upstream crate publishing
flow. The application is released from `main` without a pull request, as authorized for this plan.

## Implementation

1. Commit and tag the Laufey fork release branch, then push it.
2. Wait for the Laufey release and verify the macOS arm64 archive and checksum.
3. Commit the application changes directly to `main`, push, and publish its version tag.
4. Wait for the application release and inspect its archive structure and metadata.
5. Re-run the direct `.app` session persistence acceptance check.

## Done when

- [ ] The new Laufey tag has a successful GitHub release and verified macOS arm64 asset.
- [ ] The new application tag has a successful GitHub release and verified archive without `run.sh`.
- [ ] Direct bundle relaunch retains the authenticated Google session.
