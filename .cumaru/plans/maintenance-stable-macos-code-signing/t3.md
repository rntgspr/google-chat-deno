# T3 — Integrate signing into the release workflow

## What to do

Integrate persistent self-signed signing into the existing application deployment workflow.
Use the production identity from T2 and package the signed app for T4.

## Context

The signing target is GoogleChatDeno.app and its embedded executable code, including the incorporated
Laufey runtime. The temporary runner Keychain exists only to supply the private key to codesign.
The user's Keychain and application credential architecture are outside this task.

## Implementation

1. Consume MACOS_CERTIFICATE_P12, MACOS_CERTIFICATE_PASSWORD, and MACOS_KEYCHAIN_PASSWORD from the
   repository's Actions secrets without exposing values.
2. Decode and import the identity into a dedicated temporary runner Keychain with non-interactive
   access restricted to the signing tools.
3. Keep the pinned runtime download and existing application assembly path.
4. Sign the necessary embedded code from the inside out and then the main application bundle with
   the persistent identity, after assembly and before packaging.
5. Use the existing release mechanism and update metadata to describe self-signed signing and no
   notarization accurately.
6. Remove temporary private material and the temporary signing Keychain on success and failure.
7. Produce the release artifact for installation. Add no test jobs, signature-verification gates,
   archive re-extraction checks, or cross-build validation.

## Done when

- [ ] The existing workflow uses the persistent signing identity for official application releases.
- [ ] Private material stays out of logs and distributable artifacts and is cleaned up after signing.
- [ ] The signed release artifact is available for manual installation.
