# T1 — Reproduce menu bar and Cmd+Q behavior

## What to do

Run the app and record, with evidence, (a) what the macOS menu bar shows for the application
menu and (b) what pressing Cmd+Q does — process exits, window closes only, or nothing.

## Context

`src/main.ts` already installs a one-item application menu (`{ role: "quit" }`) at startup.
No live checkpoint has ever confirmed the role renders as a Quit item or that the shortcut
fires. The runtime's `setApplicationMenu` / `onmenuclick` semantics are undocumented
(`specs/runtime`).

## Implementation

1. Launch via `./run.sh`.
2. Inspect the menu bar; screenshot or transcribe the application menu entries.
3. Press Cmd+Q. Record the outcome and whether the process survives
   (`pgrep -f GoogleChatDeno` before/after).
4. If Cmd+Q does nothing, also click the visible Quit item if one exists — this separates
   "role not mapped to a working action" from "menu not installed".

## Done when

- [ ] Menu bar content recorded.
- [ ] Cmd+Q outcome recorded (process-level evidence).
- [ ] Failure mode attributed to menu installation vs role handling vs works-as-is.
